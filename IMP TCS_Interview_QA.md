## 1. Program to get duplicate values from an array

```java
import java.util.*;

public class DuplicateFinder {
    public static void main(String[] args) {
        int[] arr = {1, 2, 3, 4, 2, 5, 3, 6, 1};
        Set<Integer> seen = new HashSet<>();
        Set<Integer> duplicates = new LinkedHashSet<>();

        for (int num : arr) {
            if (!seen.add(num)) {   // add() returns false if already present
                duplicates.add(num);
            }
        }
        System.out.println("Duplicate values: " + duplicates);
    }
}
```
**Output:** `Duplicate values: [2, 3, 1]`

Alternative one-liner using Java 8 Streams:
```java
Arrays.stream(arr)
      .boxed()
      .collect(Collectors.groupingBy(e -> e, Collectors.counting()))
      .entrySet().stream()
      .filter(e -> e.getValue() > 1)
      .map(Map.Entry::getKey)
      .forEach(System.out::println);
```

## 4. Explain OOPs (and how you use it in your project)

The 4 pillars of OOPs:

| Concept | Meaning | How it's used in automation |
|---|---|---|
| **Encapsulation** | Wrapping data (fields) and methods together, using private fields with getters/setters | 
					WebElements declared `private`, accessed only via methods in Page classes out*** Modele/POJO classes ***
					
| **Inheritance** | A class acquiring properties of another class (`extends`) | All Page classes extend a common `BasePage`; 
					all Test classes extend `BaseTest` for common setup |
| **Polymorphism** | Same method behaving differently — method overloading (compile-time) & overriding (run-time) | 
					Overloading utility methods like `waitForElement(WebElement e)` & `waitUntilVisible(WebElement e)` & `waitUntilClickable(WebElement element)`; 
					overriding `toString()` in custom exception classes |
| **Abstraction** | Hiding implementation details, exposing only functionality | 
					Using interfaces like `WebDriver` (implementation hidden), or abstract `BasePage` with abstract methods that each page implements |

## 7. Parallel Testing (How to)

**Purpose**: Run multiple test classes/methods simultaneously to reduce execution time.

**Using TestNG `testng.xml`:**
```xml
<suite name="ParallelSuite" parallel="methods" thread-count="3">
    <test name="Test1">
        <classes>
            <class name="tests.LoginTest"/>
            <class name="tests.SearchTest"/>
        </classes>
    </test>
</suite>
```
- `parallel="methods"` → each `@Test` method runs in a separate thread
- `parallel="classes"` → each class runs in a separate thread
- `parallel="tests"` → each `<test>` tag runs in parallel
- `thread-count` → number of threads to use

**Key requirement**: WebDriver must be made **thread-safe** using `ThreadLocal<WebDriver>`:
```java
public class DriverManager {
    private static ThreadLocal<WebDriver> driver = new ThreadLocal<>();

    public static WebDriver getDriver() { 
		return driver.get(); 
		}
		
    public static void setDriver(WebDriver d) { 
	driver.set(d); 
	}
    public static void unload() { 
	driver.remove(); 
	}
}


EXAMPLE ThreadLocal ThreadLocal ThreadLocal IMPELEMENTATION

 // 1. Declare the ThreadLocal WebDriver container
    private static final ThreadLocal<WebDriver> driverThreadLocal = new ThreadLocal<>();

    @BeforeMethod
    public void setUp(){

        // 2. Initialize a new ChromeDriver instance for the current thread
        WebDriver driver = new ChromeDriver();
        driver.manage().window().maximize();

        // 3. Store the instance inside the ThreadLocal container
        driverThreadLocal.set(driver);
    }

    // 4. Create a public getter to access the driver instance safely
    public static WebDriver getDriver() {
        return driverThreadLocal.get();
    }

    @AfterMethod
    public void tearDown() {
        // 5. Retrieve the thread-specific driver instance and close it
        if (getDriver() != null) {
            getDriver().quit();
        }
        // 6. Prevent memory leaks by removing the reference from the current thread
        driverThreadLocal.remove();
    }

    @Test
    public void Test_1() {
        // Use getDriver() to launch the application
        getDriver().get("https://www.google.com");
        System.out.println("Thread 1 Title: " + getDriver().getTitle());
    }



```
This ensures each thread gets its own driver instance, avoiding conflicts.

Also mention: parallel execution across browsers/machines is achieved via **Selenium Grid** or cloud tools (BrowserStack/Sauce Labs).

## 8. What are Hooks

Depends on context — likely referring to **TestNG/Cucumber hooks**:

**TestNG "hooks" (annotations that run before/after):**
- `@BeforeSuite` / `@AfterSuite`
- `@BeforeTest` / `@AfterTest`
- `@BeforeClass` / `@AfterClass`
- `@BeforeMethod` / `@AfterMethod`

They let you set up preconditions (e.g., launch browser) and clean up afterward (e.g., close browser) without repeating code in every test.

**If Cucumber/BDD is used**, Hooks are:
```java
@Before
public void setUp() { driver = new ChromeDriver(); }

@After
public void tearDown() { driver.quit(); }
```
`@Before` runs before each scenario, `@After` runs after each scenario — used for setup/teardown, 
and can also be tagged (`@Before("@smoke")`) to run conditionally.

## 9. Difference between Implicit, Explicit & Fluent Wait

| Wait Type | Scope | Behavior | Example |
|---|---|---|---|
| **Implicit Wait** | Applies globally to *all* elements for the driver session | Polls the DOM for a fixed time before throwing 
						`NoSuchElementException` | `driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));` |
| **Explicit Wait** | Applies to a *specific* element/condition | Waits until a defined condition is true (e.g., visibility, clickability), 
						up to a max timeout | `WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10)); 
						wait.until(ExpectedConditions.visibilityOf(element));` |
| **Fluent Wait** | Applies to a specific element, more customizable | Like explicit wait, but you can set **polling frequency** and 
					**ignore specific exceptions** | See below |

```java
Wait<WebDriver> fluentWait = new FluentWait<>(driver)
        .withTimeout(Duration.ofSeconds(30))
        .pollingEvery(Duration.ofSeconds(5))
        .ignoring(NoSuchElementException.class);

WebElement element = fluentWait.until(d -> d.findElement(By.id("submit")));
```

**Key point to say in interview**: Never mix implicit and explicit waits in the same script — it can cause unpredictable wait times.

## 10. Annotations in TestNG

| Annotation | Purpose |
|---|---|
| `@BeforeSuite` / `@AfterSuite` | Runs once before/after all tests in the suite |
| `@BeforeTest` / `@AfterTest` | Runs before/after each `<test>` tag in testng.xml |
| `@BeforeClass` / `@AfterClass` | Runs once before/after the first/last test method in the current class |
| `@BeforeMethod` / `@AfterMethod` | Runs before/after **each** `@Test` method |
| `@Test` | Marks a method as a test case |
| `@DataProvider` | Supplies data for data-driven testing |
| `@Parameters` | Passes parameters from `testng.xml` |
| `@Priority` (attribute of `@Test`) | Controls execution order: `@Test(priority=1)` |
| `@Ignore`/`enabled=false` | Skips a test method |

**Execution order:** `@BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test → @AfterMethod → @AfterClass → @AfterTest → @AfterSuite`

- **Version control** — Git branching strategy (feature branch → PR → merge to main/develop).

## 13. How to automate a POST request using REST Assured

```java
import io.restassured.RestAssured;
import io.restassured.response.Response;
import io.restassured.http.ContentType;
import static io.restassured.RestAssured.given;

public class PostRequestExample {
    public static void main(String[] args) {
        RestAssured.baseURI = "https://reqres.in/api";

        String requestBody = "{ \"name\": \"John\", \"job\": \"QA Engineer\" }";

        Response response = 
			given()
                .header("Content-Type", "application/json")
                .contentType(ContentType.JSON)
                .body(requestBody)
            .when()
                .post("/users")
            .then()
                .statusCode(201)
                .extract().response();

        System.out.println("Response Body: " + response.asString());
        System.out.println("Status Code: " + response.getStatusCode());
    }
}
```

**Using a POJO instead of raw JSON string (better practice):**
```java
User user = new User("John", "QA Engineer");

given()
    .contentType(ContentType.JSON)
    .body(user)
.when()
    .post("/users")
.then()
    .statusCode(201)
    .body("name", equalTo("John"));
```

**Key REST Assured syntax to remember**: 
`given()` (request setup) → `when()` (action: get/post/put/delete) → `then()` (validation/assertions).

## 14. Authentication vs Authorization

| Aspect | Authentication | Authorization |
|---|---|---|
| **Meaning** | Verifies *who you are* (identity) | Verifies *what you're allowed to do* (permissions) |
| **Happens** | First (before authorization) | After authentication |
| **Example** | Logging in with username/password, API key, token | Accessing admin panel only if role = "Admin" |
| **HTTP Status if failed** | 401 Unauthorized | 403 Forbidden |
| **In REST Assured** | `given().auth().basic("user","pass")` or bearer token in header | 
						Checked at the server based on the authenticated user's role |

**Common auth types tested via REST Assured**: Basic Auth, Bearer Token/OAuth2, API Key in header.
```java
given().auth().oauth2("your_token_here")
       .when().get("/secure-endpoint")
       .then().statusCode(200);
```

## 15. PUT vs PATCH

| Aspect | PUT | PATCH |
|---|---|---|
| **Purpose** | Replaces the **entire resource** | Updates **only specified fields** (partial update) |
| **Idempotent?** | Yes | Technically yes, but often treated as non-idempotent in practice |
| **Payload** | Must send the complete resource object | Send only the fields you want to change |
| **Example** | `PUT /users/1` with full user JSON — missing fields may be nulled/removed | `PATCH /users/1` with `{ "email": "new@mail.com" }` — only updates email, rest untouched |

**Interview line**: "PUT is like overwriting the whole file, PATCH is like editing just one line in that file."

## 16. Exceptions

**Exception hierarchy:**
```
Throwable
 ├── Error (JVM-level, not meant to be handled — e.g., OutOfMemoryError)
 └── Exception
      ├── Checked Exception (must be handled/declared — e.g., IOException, SQLException)
      └── Unchecked/Runtime Exception (not enforced at compile time — e.g., NullPointerException, ArrayIndexOutOfBoundsException)
```

**Checked vs Unchecked:**
- **Checked**: Compiler forces you to handle with try-catch or `throws` (e.g., `IOException`, `InterruptedException`).
- **Unchecked**: Occur at runtime, not checked at compile time (e.g., `NullPointerException`, `ArithmeticException`, `ClassCastException`).

**Common Selenium exceptions asked about:**
- `NoSuchElementException` — element not found in DOM
- `ElementNotInteractableException` — element present but not interactable (hidden/disabled)
- `StaleElementReferenceException` — element reference is no longer attached to the DOM (page was refreshed/reloaded)
- `TimeoutException` — explicit wait condition not met within given time
- `NoSuchWindowException` / `NoAlertPresentException`

**Try-Catch-Finally example:**
```java
try {
    driver.findElement(By.id("nonexistent")).click();
} catch (NoSuchElementException e) {
    System.out.println("Element not found: " + e.getMessage());
} finally {
    System.out.println("This block always executes");
}
```

**Custom Exception example:**
```java
public class InvalidLoginException extends Exception {
    public InvalidLoginException(String message) {
        super(message);
    }
}
```
