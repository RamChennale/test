***3. Explain Project\Framework walkthrough

- ***Framework type***: Hybrid Framework (Data-Driven) or Page Object Model (POM) with TestNG.
- **Tools used**: Selenium WebDriver, Java, TestNG, Maven, Extent Reports, Jenkins, Git, Log4j.
- **Folder structure**: 
  - `src/main/java` → Page classes, Utility classes, Base class
  - `src/test/java` → Test classes
  - `src/test/resources` → testng.xml, config/properties files, test data (Excel/JSON)
  
- **Flow Framework structure **: 
  - `BaseClass` handles driver initialization/teardown (setup & teardown using `@BeforeSuite`/`@AfterSuite` or `@BeforeMethod`/`@AfterMethod`).
  - `PageObjects` contain locators + methods (POM design pattern, often with `PageFactory`).
  - `TestNG` classes call page methods and add assertions.
  - Data is externalized via Excel/JSON/properties files (Data-Driven Testing with `@DataProvider`).
  - Reports generated via Extent Reports; logs via Log4j.
  - Integrated with Jenkins for CI/CD — triggered on code commit or scheduled runs.
  - Failures captured via screenshots attached to reports.

I've worked on a Hybrid Automation Framework that brings together the Page Object Model (POM), third party tools TestNG, BDD Cucumber brings togather.
For automation Framework build using
1.Tech stack:
	Java
	Selenium WebDriver
	TestNG
	Maven
	Extent Reporting

2.Extent Reports for HTML-based test reports
3.Log4j for logging
4.Jenkins for CI/CD integration

5.Framework structure - Architecture (layered):
	1.	Base classes handle setup and teardown
	2.  Page classes hold element locators and actions
	3.	Test classes contain the actual validations
	4.	Utility classes cover reusable functions — reading test data, capturing screenshots, and other common operations
	5.	To keep things maintainable, the framework follows POM and pulls test data from external sources like Excel, JSON, or properties files.

For faster execution, it relies on:
6.TestNG - using as execution engine for the framework and failed Test Cases and also parallel and cross browser execution

7.A few more built-in features:

Auto-retry for failed tests
Screenshot capture on failure
Environment config management (QA/UAT/Prod)
Dynamic test data generation via Faker

8.Challenges faced: Flaky tests and data conflicts during parallel runs — solved using explicit waits, better synchronization.
